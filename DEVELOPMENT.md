### Known environment quirks

1. **`npx expo install` fails with `EALLOWSCRIPTS`.** Your `~/.npmrc` sets `allow-scripts`. When npm
   runs under `npx`, it passes that setting to child npm processes as a CLI-level setting, and
   npm 11.19 rejects that for project installs. Call the local binary instead:
   ```bash
   ./node_modules/.bin/expo install <pkg>
   ```
2. **Blocked install scripts.** npm 11 blocks install scripts by default. `esbuild`, `fsevents`,
   `@parcel/watcher` and `unrs-resolver` are currently blocked; none is needed (tsx, Jest and Metro all
   work). Review with `npm install-scripts ls`.
3. **`react-dom` is pinned to 19.3.0** so that it matches `react@19.3.0`. Without the pin, npm picks
   19.3.1, which has a peer conflict.
4. **TypeScript 6 defaults `types` to `[]`.** `tsconfig.json` declares `"types": ["jest"]`. Node
   scripts add `/// <reference types="node" />`.
5. **RNTL 14 is async.** `render`, `fireEvent.*` and `rerender` return promises, so always `await` them.
6. **Reanimated in Jest.** Reanimated 4.7 can't load under jest-expo's iOS preset (its native
   initializer calls `setCSSEventHandler`), and `react-native-reanimated/mock` imports the real
   entry point. `moduleNameMapper` points `react-native-reanimated` at `test/mocks/reanimated.ts`
   and `react-native-reanimated/mock` at `test/mocks/reanimated.impl.ts`. They must be separate
   files, because `expo-router/testing-library` re-mocks Reanimated by requiring `/mock` inside its
   factory. Extend the mock when you adopt new Reanimated APIs.
7. **Stale Jest cache.** After changing mocks or `jest.setup.ts`, run `npx jest --clearCache` if
   results look inconsistent.
8. **Skia 2.14 paths are immutable** (built through `SkPathBuilder`). The renderer passes SVG path strings to
   `<Path path=…>`, which avoids the builder entirely.

## Commands

```bash
npm run typecheck        # tsc --noEmit
npm test                 # all Jest suites
npm run test:engine      # engine + level suites only
npm run validate-levels  # schema + solver validation of every shipped level
npm run generate-levels  # regenerate planned levels into src/levels/data/*.generated.json
npm run synthesize-sfx   # regenerate assets/audio/*.wav (original, deterministic)
npm run render-brand-assets  # regenerate icon/splash/adaptive icons (original, deterministic)

npm run lint             # eslint (type-aware promise rules, engine purity)
```

`ios/` and `android/` are generated by Continuous Native Generation and are gitignored. Configure
native behaviour only in `app.json` and config plugins.

## Architecture rules

- **`src/engine` is pure.** It has no React, React Native or Expo imports. Every transition goes through
  `gameReducer(state, action)`, which returns the *same object* when nothing changes. Tests rely on this.
- **Determinism.** Power BFS visits tiles in index order. The PRNG is `mulberry32` with an FNV-1a
  string hash, and pinned reference values in tests catch accidental algorithm changes. If either
  must change, bump the generator version so historical daily challenges stay reproducible.
- **Levels are validated before rendering.** The registry runs `validateLevel` on every level at
  startup and drops invalid ones; in dev, the root layout logs them as a warning. The validator never throws.
- **Optimality claims are checked.** A level may set `optimalMoves` only when
  `solutionMetadata.optimality === 'proven'`. `npm run validate-levels` re-proves every claim
  with the solver and fails the build on any mismatch.
- **Rendering vs input.** A single Skia `<Canvas>` draws the board. `TileHitGrid` sits on top:
  - **Touch:** raw `onTouchStart`/`onTouchEnd`, tracked per finger. Don't use `Pressable` for board
    cells: its single-responder model dropped overlapping taps (two thumbs, or fast tapping while
    JS is busy). This was reproduced on the simulator with a two-finger tap.
  - **VoiceOver:** each cell is an accessible `View` with role `button`, a label, and an `activate`
    action. Targets are ≥ 44pt.
- **Overlays never animate out.** A Reanimated `exiting` animation keeps the full-screen scrim
  mounted, and it swallowed taps right after Resume.
  Board width is capped at 7 so cells stay ≥ 44pt on a 375pt-wide phone.
- **Reduced motion.** `useReduceMotion()` combines the OS setting with the in-app override. With it on,
  rotations snap, power appears without a stagger, and glows don't pulse.
- **Monetization adapters (Phase 6)** each expose an explicit `disabled` state. Entitlements come
  only from the store SDK, never from local flags.

## Audio, feedback and accessibility

- **Sound effects** are synthesized by `scripts/synthesize-sfx.ts`. No third-party audio is used,
  so there is nothing to license. Edit the voices there and rerun.
- `services/audio.ts` sets an **ambient** session (`playsInSilentMode: false`, `mixWithOthers`).
  If it can't configure audio, it disables itself and never throws into gameplay.
- `services/feedback.ts` is the one entry point per game event: sound plus haptic, each respecting
  its own toggle.
- **Contrast** is enforced by `src/ui/__tests__/contrast.test.ts`. Add new colour pairs there when
  you add tokens.
- **Never use colour alone:** signal colours have glyphs (circle/diamond), and shorts have a broken
  wire core.
- **VoiceOver:** tile labels describe orientation and state, and `describeChange` announces power,
  shorts and completion after every move.
- **Dynamic Type:** use `fontScale` caps only on dense fixed-layout labels; body text scales fully.

## Storage

`src/storage` keeps SQLite behind `SqlDatabase` (`sql.ts`). The app uses `expoDatabase.ts`; tests use
`test/sqlite/nodeDatabase.ts` (Node 24's built-in `node:sqlite`, in memory), so migrations and
queries run against a real engine.

- **Migrations** (`migrations.ts`): append-only, numbered 1..n, tracked in `PRAGMA user_version`.
  Each migration runs in one transaction with its version bump. A database from a newer build throws
  `MigrationError('newerSchema')`, and the app then runs from memory instead of risking data loss.
- **Persistence** (`persistence.ts`): loads the stores at startup, then subscribes to them. Stores
  never import storage code. All writes go through one serialized queue.
- **Sessions:** one resume slot. Snapshots carry a level fingerprint (`levels/fingerprint.ts`); a
  mismatch discards the snapshot, so it is never replayed onto an edited level.
- **Entitlements are deliberately not stored here** (Phase 6: they come from the store SDK only).

## Generator and level data

- `src/engine/generator.ts` (`gen-1`): deterministic for a given spec. Attempt `a` seeds from
  `hash("gen-1:<seed>:<a>")`. **Any change to the output for an existing seed needs a new version
  string.** New rejection filters that consume no randomness are safe.
- `src/levels/plans.ts` holds the curated per-level specs. `npm run generate-levels` writes
  `src/levels/data/<chapter>.generated.json`. Review the diff and commit it. A test regenerates every
  planned level and fails on any difference.
- Hand-built levels (tutorials) use the grid notation below.

## Monetization, ads, analytics (Phase 6)

Everything ships **disabled until configured**. Nothing in the client grants a purchase or a reward
without a store or ad-SDK confirmation.

| Piece | Code | Disabled when |
|---|---|---|
| Purchases (RevenueCat) | `services/purchases/` | `EXPO_PUBLIC_REVENUECAT_IOS_KEY` / `_ANDROID_KEY` unset |
| Rewarded ads (AdMob) | `services/ads/` | release build without `EXPO_PUBLIC_ADMOB_REWARDED_IOS` / `_ANDROID` (dev builds use Google's test unit) |
| Analytics | `services/analytics/` | always, until a vendor sink is installed **and** the player opts in |

**Invariants (each covered by tests):**
- Entitlements live only in memory (`state/entitlementStore.ts`). They are filled solely from
  RevenueCat's verified customer info and never stored in SQLite; the schema has nowhere to put them.
- Rewarded hints: `rewardFlow.ts` grants only after the SDK's `EARNED_REWARD` callback, and
  `useGame().requestRewardedHint(outcome)` refuses any outcome other than `rewarded`.
- Ads are rewarded only (no banners, interstitials or app-open ads), shown only at the player's request,
  and the game pauses while one is on screen. Requests are non-personalized, so there is no ATT prompt.
- Consent (Google UMP) is gathered the first time a player asks for an ad, not at launch.
- Premium chapters (`Chapter.premium`) require the verified `premium_content` entitlement in
  `levels/progression.ts`.

### Setting up RevenueCat
1. App Store Connect: create three **non-consumable** products (IDs of your choice).
2. RevenueCat: create entitlements named exactly **`no_ads`** and **`premium_content`**. Attach
   remove-ads → `no_ads`, premium chapter → `premium_content`, founder bundle → both.
3. RevenueCat: in the **current** offering, add packages with identifiers **`remove_ads`**,
   **`premium_chapter`** and **`founder_bundle`**.
4. Set `EXPO_PUBLIC_REVENUECAT_IOS_KEY` (the *public* SDK key) in the EAS environment. Never use a
   secret key in the client.

### Setting up AdMob
1. Create the app in AdMob and a **rewarded** ad unit.
2. Set `ADMOB_IOS_APP_ID` (build time; `app.config.ts` **fails production builds without it**) and
   `EXPO_PUBLIC_ADMOB_REWARDED_IOS`.
3. AdMob → Privacy & messaging: publish a GDPR (and, if applicable, US state) consent message.
   Without one, UMP returns "no form(s) configured", and release builds then show no ads (by design).
4. Development builds use Google's sample app ID and test unit. Because the sample ID has no consent
   form, a **dev-only** bypass (`devBypassMissingConsentConfig`) lets test ads run so the reward flow
   can be exercised. It is gated on `__DEV__` and the test unit.
5. Optional hardening: server-side verification (SSV) of rewards, which needs a backend.

### Analytics
`services/analytics/events.ts` is the typed catalogue (11 events, no personal data).
`initAnalyticsBridge()` derives gameplay events from store transitions. To add a vendor, implement
`AnalyticsSink` and call `setAnalyticsSink()` at startup, then update the privacy policy and App Store
privacy labels. `EXPO_PUBLIC_ANALYTICS_DEBUG=1` logs events to the console in dev builds.

### Native config gotcha
After changing config plugins (for example AdMob app IDs), run `npx expo prebuild --platform ios`
before `expo run:ios`. `run:ios` does not re-run prebuild when `ios/` already exists. Missing this
caused a `GADInvalidInitializationException` launch crash during Phase 6.

## Progression, hints, daily, tutorial

- `levels/progression.ts` holds all unlock rules (pure, tested). Every screen and the play route go
  through it, so a deep link can't open a locked level. Phase 6 adds an entitlement check for
  premium chapters in the same place.
- Hints: `play/hintPolicy.ts` (`FREE_HINTS_PER_LEVEL = 3`, interim) and `useGame().requestHint()`.
- Daily: `levels/daily.ts`. **Never edit an existing entry of `DAILY_GENERATOR_SCHEDULE`**; append a
  new `{ from, version }` when a new generator ships. Pinned fingerprints in
  `levels/__tests__/daily.test.ts` guard historical puzzles.
- Tutorial: `play/tutorial.ts` (steps per level); the state is stored in settings as `tutorial`.

## Solver

`solve(puzzle, board, limits)` does a layered BFS over **tap counts** per rotatable tile. Taps on
different tiles commute, so the first layer that contains a solved state is the proven minimum.
Symmetric orientations are collapsed: a straight piece has 2 distinct states, and a cross or empty tile has 1.
Results:

- `optimal`: minimum moves plus the solution rotations
- `unsolvable`: the whole space was searched and no solution exists
- `unknown`: the state or time limit was hit. This never counts as solved or optimal.

`solveSearch` (`dfs-bb-1`) is a row-major DFS with branch-and-bound. On strict levels
(`noOpenEnds` + `allTilesPowered`), every open port must meet a reciprocal port, so each orientation
must agree with its already-placed neighbours. That pruning is exact. A completed search proves the
optimum. A cut-off search that holds a solution returns `feasible`, which is an upper bound and is
never shown as "Optimal". `solveAuto` chooses between the two solvers. A property test checks the
DFS against the BFS on 60 generated boards.

`nextHint(puzzle, currentBoard)` solves from the player's **current** board, so hints stay correct
after wrong moves.

## Authoring levels by hand

`src/levels/author.ts` defines a compact grid notation. Write the start (scrambled) grid and the solved
grid, then run `npm run validate-levels`. Set `provenOptimal: true` only once the script confirms
that the solver proves the par minimal.

```
.  empty     #  blocked     S<r> source     R<r> receiver
I<r> straight   L<r> elbow   T<r> tee   X cross        modifiers: * (toggle lock)  v (violet)
```
